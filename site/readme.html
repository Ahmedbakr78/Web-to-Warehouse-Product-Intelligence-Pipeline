Web-to-Warehouse Product Intelligence Pipeline — DEPI graduation project, Data Engineering track. Thirty-seven documents covering the proposal, planning, requirements, design, implementation evidence and evaluation.

Every diagram is Mermaid, rendered natively by GitHub and to SVG for the static site. Every structural number is measured by a script and re-verifiable with the command cited beside it.

How to read these numbers

Structural figures are exact and re-verifiable:

Claim Verify with
29 tables, 23 views make bootstrap, or make stats
222 REST operations in 23 routers http://localhost:8000/docs, or make stats
408 tests pass make test
104 API smoke checks pass .venv/bin/python scripts/api_smoke.py
ruff and mypy clean make lint and make typecheck
No schema drift make db-check
100+ Mermaid diagrams make docs-render
12 DQ rules and the score Quality screen, or pip-cli quality

scripts/project_stats.py recounts all of these, scripts/check_stats.py fails when a documented figure no longer matches reality, and make stats-check runs it in CI. A number in these documents is therefore either measured or checked.

Row counts and latencies are measurements, not constants. They depend on how much data a given database holds and on the hardware. Each figure records the measurement taken at a stated moment — generally the development machine at the stated date — and is not silently rewritten when a later run produces a different number. Where a document reports a dataset size, the command that regenerates it is named alongside.

Reading order

If you are reviewing this for the first time:

  • 01 Project Proposal — what problem, and why.
  • 08 System Analysis and

21 Architecture Deep Dive — how it is built and why each decision was made.

  • 25–30 — the newer subsystems:

forecasting, jobs and realtime, reporting, migrations, two-factor, access control.

  • 33 Data Trust & Compliance — how the

warehouse guarantees that every row was really observed.

  • 36 Decision Log — why the system is the way it is,

including the alternatives that were rejected.

  • 14 API Documentation and

16 User Manual — the two views most reviewers want.

  • 15 Testing Strategy — what is verified, and how.
  • 24 Demo Runbook — if you are seeing it live.

Quick commands

make help          # every target
make up            # the six-service stack
make bootstrap     # schema, views and demo users
make demo-postgres # deterministic 120-day dataset
make run-pipeline  # one pipeline run
make verify        # the full quality gate
make docs-build    # regenerate the static site from this Markdown
make docs-render   # render every Mermaid diagram to SVG
make stats         # measured structural counts
make infographic   # the 2560x1440 DEPI poster
