2. About — full description (recommended, paste verbatim)

Web-to-Warehouse Product Intelligence Pipeline — a production-style DEPI Data Engineering capstone that continuously collects product information from permitted public web sources and merges it with an internal catalogue. It respects robots.txt, rate limits and website terms before it fetches a single record; cleans and normalises names, categories, prices, ratings and availability; detects exact and fuzzy duplicates; then loads a Kimball-style warehouse on PostgreSQL and MySQL with full price-history snapshots. SQL analytics answer price changes, new products, removed products and category drift, while Apache Airflow orchestrates the nine-stage run. A FastAPI service exposes 222 REST operations (OpenAPI/Swagger included) and a React 19 dashboard renders 23 screens with light/dark/system themes, a mobile off-canvas sidebar and silent in-place reloads. 767 catalogued features · 34 registered sources · 12 enforced data-quality rules · 29 tables · 23 analytical views · 634 passing tests · 104/104 API smoke checks. Zero fake data: a dedicated audit proves every row traces back to a real, permitted source.

6. Release notes — v1.12.1

# v1.12.1 — "Nothing is a stub any more"

The theme of this release is completeness: every panel is backed by real data,
every control changes behaviour, and the documentation matches the code.

## Added
- 767 catalogued features across 46 areas, browsable in-app with search and export.
- 222 REST operations with OpenAPI/Swagger, pagination, filtering and rate limiting.
- 29 warehouse tables + 23 analytical views, on PostgreSQL and MySQL.
- 12 enforced data-quality rules, 34 registered sources, Airflow DAG and backfill.
- Light / dark / system themes, mobile off-canvas navigation, silent reloads.
- Forecasting, anomaly detection, briefing, webhooks, 2FA, sessions, reports and exports.

## Fixed
- Portable variance sign in the analytics service and both SQL views.
- Rating vote counts discarded for API sources.
- Fake category-change events caused by cross-source category disagreement.
- `make install` on a fresh clone (invalid `scrapy-rotating-proxies` pin).
- Full verification no longer fails when an upstream tightens its robots.txt.

## Verified
- 632 backend tests, 67 frontend tests, ruff, mypy, typecheck, lint, production build.
- Live real-source pipeline: no-fake audit CLEAN, every row traced to a permitted source.

8. Manual touches (GitHub UI only)

  • Settings → General → Social preview → upload a 1280×640 image.
  • Pin the repository on your profile.
  • Settings → Pages → Source: main / docs if you want the HTML site hosted.
  • Settings → General → Features → enable Issues, Projects and Wiki as desired.
  • Add the team as collaborators with the roles in docs/00_team.md.

9. Safety — what is never touched

No files, branches, tags, issues, releases or repository content are deleted. --add-topic only appends topics; gh release create is skipped when a tag already exists; visibility change is limited to the requested private setting.
