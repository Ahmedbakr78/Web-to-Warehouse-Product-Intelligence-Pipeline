The problem

Manual collection is slow, inconsistent, and destroys the history that makes pricing decisions possible.

Slow

  • Analyst hours spent copying prices into spreadsheets
  • A refresh cycle measured in days, not minutes

Inconsistent

  • Same product named three ways
  • Currencies and formats never normalised

Amnesiac

  • No history, so no trend
  • No audit trail, so no defensible claim
The question nobody can answer: what did this product cost last March, and on whose authority?

Objective and scope

Collect permitted product data, standardise it, resolve duplicates, and load it into an analytical database that answers business questions.

In scope

  • Scrape permitted structured product information
  • Respect robots.txt, rate limits and website terms
  • Clean names and categories; normalise currencies
  • Detect duplicates and compare against the internal catalogue
  • Load into PostgreSQL / MySQL with historical snapshots
  • Identify price, new, removed and category changes with SQL
  • Orchestrate with Airflow; expose the result over REST

Deliberately out of scope

  • Bypassing any site's protections
  • Personal or behavioural data
  • Real-time streaming ingestion
  • Training a machine-learning model
  • Anything not evidenced by a test

Compliance is evidence, not a claim

The ingestion layer is where a scraper earns the right to run.

Enforced in the fetch layer

  • robots.txt parsed and its verdict recorded per request
  • Per-source rate limits and crawl-delay honoured
  • Conditional requests and an on-disk cache
  • An identifying User-Agent with a contact address

Recorded as proof

  • Every request logged with URL, status and elapsed time
  • The robots verdict stored alongside each request
  • Cache hits distinguished from live fetches
  • One audit row per pipeline run, queryable by screen
A reviewer can reconstruct what was fetched, when, and whether it was permitted without reading the code.

Beyond history: what the data says next

History is already in the fact table. These three things are not.

Forecasting

  • Damped Holt-Winters with two-sided bands
  • Accuracy measured on a held-out tail, never on the fit

Anomaly detection

  • MAD, 3&sigma; and IQR fences run together
  • Two of three must agree, so an outlier cannot pass its own test

Pricing advice

  • Category elasticity
  • Raise, cut, hold or negotiate &mdash; with the reason stated
Where the history is too short, the API returns a flat series with wide bands rather than a confident-looking curve.

What made it hard, and what was done about it

Duplicate resolution

  • The same product appears under three names on three sites
  • Blocking keys to bound the comparison set
  • A similarity threshold, with the strategy recorded per match

Rebuilding a schema in place

  • create_all cannot express a change, a rollback or a history
  • Alembic adopted; Airflow metadata moved to its own database

Realtime across workers

  • An in-memory broker only sees its own process
  • Events now also polled from a persisted log
The one that was not caught by any static check: an external store returning a new snapshot object per call, which put every screen into an infinite render loop. It is now pinned by a test.
